AWS Security Auto Remediation - 보안 그룹 위험 규칙 자동 조치

CloudTrail과 EventBridge로 위험한 SSH 인바운드 규칙 생성을 감지하고, Lambda가 규칙을 자동 제거한 뒤 로그와 알림으로 조치 결과를 남기는 보안 자동 대응 프로젝트입니다.

GitHub Repository 프로젝트 목록

1. 프로젝트를 진행한 이유

운영자가 모든 보안 그룹 변경을 수동으로 확인하는 방식의 한계를 줄이기 위해 이벤트 기반 자동 조치 흐름을 실습했습니다.

탐지, 자동 조치, 규정 준수 평가, 감사 로그, 알림을 각각 구분해 보안 운영 흐름을 구성하는 것을 목표로 했습니다.

3. 사용한 기술과 선택 이유

  • CloudTrail — AuthorizeSecurityGroupIngress API 이벤트를 기록합니다.
  • EventBridge — 보안 그룹 인바운드 규칙 생성 이벤트를 실시간으로 필터링합니다.
  • Lambda — 0.0.0.0/0에 열린 SSH 규칙을 확인하고 자동 제거합니다.
  • AWS Config — 별도 테스트 보안 그룹을 restricted-ssh 규칙으로 평가합니다.
  • CloudWatch Logs / SNS — 자동 조치 결과를 기록하고 이메일로 알립니다.
  • S3 / Terraform — 감사 로그를 보관하고 전체 리소스를 코드로 구성합니다.

4. 구현 흐름

  1. 관리자가 테스트 보안 그룹에 0.0.0.0/0 SSH 인바운드 규칙을 추가합니다.
  2. CloudTrail이 AuthorizeSecurityGroupIngress 이벤트를 기록합니다.
  3. EventBridge Rule이 해당 이벤트를 감지해 Lambda를 호출합니다.
  4. Lambda가 변경된 규칙의 포트와 CIDR을 확인합니다.
  5. 위험 조건에 해당하면 해당 SSH 규칙을 자동 제거합니다.
  6. CloudWatch Logs에 조치 결과를 기록하고 SNS 이메일을 전송합니다.
  7. AWS Config는 별도 Config Test SG의 NON_COMPLIANT 상태를 평가합니다.
  8. CloudTrail과 Config 관련 로그는 S3 Audit Bucket에 보관합니다.

5. 테스트 결과

  • Remediation Test SG에 SSH 전체 공개 규칙을 추가한 뒤 자동 삭제되는지 확인했습니다.
  • CloudWatch Logs에서 감지 대상, 조치 결과, 실패 여부를 확인했습니다.
  • SNS 이메일로 자동 조치 알림이 전송되는지 확인했습니다.
  • Config Test SG에서 restricted-ssh 규칙의 NON_COMPLIANT 상태를 확인했습니다.
  • Terraform으로 리소스를 생성하고 실습 후 삭제했습니다.

6. 트러블슈팅

테스트 보안 그룹 혼동

CONFIG_TEST_SG_ID와 REMEDIATION_TEST_SG_ID를 분리해 테스트 목적을 명확히 했습니다.

Lambda 권한 부족

Describe와 Revoke에 필요한 최소 권한을 IAM Role에 추가했습니다.

EventBridge 이벤트 패턴 불일치

CloudTrail 이벤트의 source, detail-type, eventName 구조에 맞춰 패턴을 수정했습니다.

GitHub 코드 줄바꿈 문제

.gitattributes를 추가해 Terraform과 Python 파일이 정상 줄 수로 표시되도록 수정했습니다.

7. 보안·비용·운영 관점에서 신경 쓴 점

  • 이벤트 감지와 규정 준수 평가를 분리해 각각의 목적을 명확히 했습니다.
  • 위험한 규칙을 자동으로 되돌리고 조치 내역을 로그와 이메일로 남겼습니다.
  • EC2 없이 보안 자동화에 필요한 관리형 서비스만 구성했습니다.
  • Terraform으로 보안 리소스와 권한 구성을 변경 이력으로 관리했습니다.

8. 프로젝트를 통해 배운 점

보안 자동화는 규칙을 삭제하는 기능뿐 아니라 어떤 이벤트를 탐지했는지, 어떤 권한으로 조치했는지, 결과가 어디에 기록되는지까지 설계해야 한다는 점을 배웠습니다. 탐지와 조치를 분리하면 운영 흐름을 더 명확하게 설명할 수 있음을 확인했습니다.

9. 향후 개선 방향

  • 허용 대상 계정, 태그, 보안 그룹별 예외 정책을 추가합니다.
  • 조치 실패 시 재시도와 별도 실패 알림을 구성합니다.
  • Security Hub 또는 IAM Access Analyzer 이벤트로 범위를 확장합니다.
  • 다른 위험 포트와 IPv6 전체 공개 규칙도 탐지하도록 확장합니다.
