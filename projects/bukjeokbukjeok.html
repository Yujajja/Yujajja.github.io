Team Project · Infra / Monitoring

북적북적 — 하이브리드 기반 AI 도서 추천 서비스

온프레미스 Kubernetes 메인 서비스와 AWS EKS Failover 영역을 포함한 하이브리드 구조에서 모니터링 구성, 알림 연동, 부하·장애 검증을 담당했습니다.

팀 프로젝트 포트폴리오 프로젝트 목록

1. 프로젝트 개요와 담당 역할

북적북적은 하이브리드 환경에서 운영되는 AI 도서 추천 서비스입니다. 저는 Infra / Monitoring 역할로 Prometheus와 Grafana 기반 모니터링, AlertManager와 Slack 알림 연동, Locust와 Chaos Mesh를 활용한 부하·장애 실험을 담당했습니다.

2. 전체 아키텍처

  • 온프레미스 Kubernetes 영역을 메인 서비스로 구성했습니다.
  • AWS EKS 영역은 클라우드 Failover 구조로 활용했습니다.
  • 별도 영역에서 RDS, Prometheus, Grafana, OpenSearch를 중앙 관리했습니다.

3. 사용 기술

  • Infrastructure — AWS EC2, EKS, VPC, S3, CloudFront, Route 53, RDS, OpenSearch
  • Container — Kubernetes, Docker, HPA
  • Monitoring — Prometheus, Grafana, AlertManager, Slack
  • Test — Locust, Chaos Mesh
  • CI/CD — GitHub Actions, Argo CD

4. 담당 구현 흐름

  1. Prometheus 수집 지표를 기준으로 Grafana 대시보드를 구성했습니다.
  2. AlertManager와 Slack을 연동해 이상 상태 알림 수신 흐름을 확인했습니다.
  3. Locust로 트래픽을 발생시키고 CPU와 Memory 부하 상황을 검증했습니다.
  4. Chaos Mesh를 활용해 Memory Stress와 Redis 장애를 재현했습니다.
  5. 실험 결과를 바탕으로 에러율, HPA 동작, 응답시간과 Cache Hit 변화를 확인했습니다.

5. 테스트와 검증 결과

  • CPU / Memory 부하 상황에서 HPA가 2개에서 3개로 스케일 아웃되는 것을 확인했습니다.
  • 스케일 아웃 과정에서 에러율 0%를 유지했습니다.
  • Redis 장애 시 Cache Hit율이 100%에서 0%로 감소하고 평균 응답시간이 증가하는 것을 확인했습니다.
  • 장애 상황에서 Slack Alert가 정상적으로 수신되는 것을 확인했습니다.

6. 트러블슈팅

Memory StressChaos 적용 후 OOMKill 발생

초기 부하 주입에서 OOMKill이 발생하며 에러율이 5.41%까지 증가했습니다. 원인을 분석한 뒤 부하 주입량을 조정해 에러율을 0%로 개선했습니다.

7. 운영 관점에서 신경 쓴 점

  • 지표를 시각화하는 데서 끝내지 않고 실제 장애 상황에서 알림이 수신되는지 검증했습니다.
  • HPA가 동작하는지뿐 아니라 스케일 아웃 중 서비스 에러율도 함께 확인했습니다.
  • Redis 장애 시 Cache Hit와 응답시간 변화를 비교해 캐시 장애가 서비스에 미치는 영향을 확인했습니다.

8. 프로젝트를 통해 배운 점

모니터링은 대시보드를 만드는 작업만이 아니라, 장애를 재현하고 지표와 알림이 실제 운영 흐름에서 유효한지 검증하는 과정이라는 점을 배웠습니다.

9. 향후 개선 방향

  • Cache Miss 전용 메트릭을 추가해 Redis 장애 영향을 더 명확하게 확인합니다.
  • 캐시 장애 시 RDS Fallback 흐름과 DB 부하를 함께 검증합니다.
  • Failover 전환 조건과 복구 절차를 Runbook 형태로 구체화합니다.
